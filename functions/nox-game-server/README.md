# NOX Game Server (Appwrite Function)

Initial server-authoritative room service for NOX KISS. This is a backend foundation, not a complete game engine.

## Supported actions

Send a JSON POST to the deployed Function execution URL:

- `room.create` — creates a waiting room and a six-character join code.
- `room.join` — claims one of 15 numbered seats. Seat document IDs are deterministic per room/seat so simultaneous claims cannot occupy the same seat.
- `room.leave` — releases the caller's seat.
- `room.snapshot` — returns room metadata and occupied seats.
- `room.start` — owner-only; starts after at least two players have joined.

Every request must include the signed-in Appwrite user's JWT in `X-Appwrite-JWT`. The function verifies the JWT with Appwrite Account before using its server API key. Never expose the API key in browser code.

## Required Function environment variables

- `APPWRITE_ENDPOINT` = `https://fra.cloud.appwrite.io/v1`
- `APPWRITE_PROJECT_ID` = the NOX project ID
- `APPWRITE_API_KEY` = server-side secret with only the required Database read/write scopes
- `NOX_DATABASE_ID` = `nox_core`
- `NOX_ROOMS_COLLECTION_ID` = collection ID created for rooms
- `NOX_SEATS_COLLECTION_ID` = collection ID created for room seats
- `NOX_ALLOWED_ORIGIN` = exact production web origin (avoid `*` in production)

## Database setup

Create two collections in database `nox_core` before deploying:

### Rooms collection

| Attribute | Type | Required |
|---|---|---|
| code | string(6) | yes |
| title | string(48) | yes |
| ownerId | string(36) | yes |
| status | enum/string | yes |
| maxSeats | integer | yes |
| roundNumber | integer | yes |
| currentTurnSeat | integer, nullable | no |

Create a unique index on `code`.

### Seats collection

| Attribute | Type | Required |
|---|---|---|
| roomId | string(36) | yes |
| userId | string(36) | yes |
| seatIndex | integer | yes |
| displayName | string(32) | yes |
| role | string | yes |
| ready | boolean | yes |

Create indexes on `roomId`, `userId`, and a compound index on `roomId, userId`. Seat document IDs are generated by the function as `{roomId}_{seatIndex}`.

Use collection-level permissions that allow authenticated users to read the records required for snapshots. Keep writes restricted to the server function's API key; do not grant clients direct create/update/delete access to rooms or seats. The function enforces ownership and membership checks for its supported actions.

## Realtime

Subscribe the web client to document events for the Rooms and Seats collections after the collections exist. Realtime is for delivery/refresh only; the function remains authoritative for room actions. Do not treat a client-side event or client-supplied seat count as trusted state.

## Deployment checklist

1. Create the two collections and attributes/indexes above in Appwrite Console.
2. Create an Appwrite Function using Node.js 20+ and upload this directory.
3. Add the environment variables above; store `APPWRITE_API_KEY` only as a Function secret.
4. Deploy the Function and note its Function ID.
5. Connect the browser client using the signed-in user's JWT; never ship the API key.
6. Add Realtime subscriptions and test two accounts in separate browsers.
7. Test concurrent attempts for the same seat, room capacity, owner-only start, leaving, and reconnect/snapshot recovery.

## Current limitations

- This first slice does not yet implement turn advancement, ready toggles, moderator management, private rooms/invites, chat, Spotify queue, round history, or matchmaking.
- Appwrite database schema and Function deployment are not created by this source commit.
- Capacity is bounded by 15 deterministic seat IDs. Room code uniqueness should be enforced by the database unique index; collision retry can be added if needed.
- Review API-key scopes, collection read permissions, CORS, rate limits, and abuse controls before production.
